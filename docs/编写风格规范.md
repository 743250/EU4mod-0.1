# 编写风格规范

### 文档定位

这份文档只规定本模组 EU4 脚本怎么写才算风格合格。机制目标看 `docs/幕府系统设计文档.md`，基础字段骨架看 `docs/EU4模组脚本与GUI基础格式.md`。风格样例来自女仆 mod（`Maid_nations`），规范版式学自 `提示词编写规范.md`：先给模板，再给原文，再逐条解析为什么这样写。

### 风格模板

```text
文件：按机制切开，前缀统一，不往大杂烩里继续塞。
命名：本模组新内容用 mf_*。
注释：只写短中文，贴在难懂的名字或作用域跳转旁。
可见：is_visible / potential / trigger 只回答「什么时候出现」。
允许：is_allowed / allow 只回答「点了能不能做」。
效果：on_accept / effect / option 只写直接会发生的事。
拆分：一对相反动作写成两个短块，不堆进一个超长块。
```

### 原文

女仆 `common/new_diplomatic_actions/ms_dip_generic.txt` 里转文化的一对动作：

```text
ms_dip_start_change_culture = { #转文化开始
    category = influence
    require_acceptance = no
    is_visible = {
        ai = no
        FROM = {
            is_subject_of = ROOT
            is_any_maid_subject = yes
            NOT = { has_country_modifier = ms_is_changing_culture_mod }
        }
    }
    is_allowed = {
        FROM = {
            culture_group = ROOT
            OR = {
                is_any_maid_state = yes
                is_any_maid_colony = yes
            }
        }
    }
    on_accept = {
        FROM = {
            add_country_modifier = { name = ms_is_changing_culture_mod duration = -1 }
        }
    }
}
ms_dip_end_change_culture = { #转文化结束
    is_visible = {
        ai = no
        FROM = {
            is_subject_of = ROOT
            is_any_maid_subject = yes
            has_country_modifier = ms_is_changing_culture_mod
        }
    }
    is_allowed = { always = yes }
    on_accept = {
        FROM = {
            remove_country_modifier = ms_is_changing_culture_mod
        }
    }
}
```

### 解析

#### 1. 文件和命名

原文按外交、事件、effect 切开，文件名 `ms_dip_*`、`ms_evt_*`、`ms_efx_*`。一个文件只装一类入口。

本模组新内容用 `mf_*`，不要继续往 `BL_*` 大文件里塞。旧文件只留入口调用。

#### 2. 注释

原文是 `#转文化开始` 这种短中文，贴在块名后面。不写英文，不写排查过程，不把整段旧脚本注释留下来。

简单自明的 `add_prestige` 一行不要硬注释。作用域跳转、变量、UI flag 才值得写一句。

#### 3. `is_visible`

这个字段只回答：这个入口什么时候出现。

原文只写了玩家、目标是自己的女仆属国、当前没在转文化。没有再叠一串「不是将军、不是大名、不是陪臣、不是 sort_of_mf」。

能被上一级条件盖住的排除，不要再写一遍。

#### 4. `is_allowed`

这个字段只回答：看见了以后，点下去能不能做。

原文把「同文化组、是女仆国家或殖民地」放在这里，因为这些是点下去才要卡的门槛，不是藏按钮的理由。结束动作的 `is_allowed` 直接 `always = yes`，不假装还有一层判断。

该藏的进 `is_visible`，不该把「根本不该看见」写成点了才灰掉。

#### 5. `on_accept`

只写直接效果。原文开始就是加 modifier，结束就是删 modifier。没有先套三层 `if` 防「可能已经是这个状态」。

能直接执行的效果直接写。

#### 6. 拆成两个短块

开始和结束是一对相反动作，原文写成两个独立外交，而不是一个动作里用一堆 flag 分叉。

本模组里如果一个外交/事件已经超过「入口-门槛-一句效果」，先考虑拆，不先抽新的 scripted trigger。

#### 7. 不要做的事

- 不要为了整齐新增 scripted trigger。现成的可以继续用。
- 不要在 `is_visible` 里同时堆 3 个以上幕府体系排除。
- 不要把整段旧逻辑注释留在文件里。
- 不要整文件重排、批量格式化、改编码。中文注释文件只做补丁级替换。
- 不要用英文注释。

### 结构总结

```text
定位：这页只管怎么写
  → 模板：文件 / 命名 / 可见 / 允许 / 效果 / 拆分
  → 原文：女仆里一段真正在用的短外交
  → 解析：每个字段回答什么、写什么、不写什么
  → 禁止：本模组已经踩过的反例
```

对照检查时只问四句：入口看见了吗，门槛该不该灰，效果是不是一句能做完，这个块是不是其实该拆开。
